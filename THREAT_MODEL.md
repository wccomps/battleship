# Threat Model

Battleship turns volunteer requests into queued jobs that run against Proxmox using the submitter's own Proxmox ticket. [`ARCHITECTURE.md`](ARCHITECTURE.md) describes how jobs, locks, and packages fit together; this document records the security boundaries, secret invariants, sharp edges, and accepted risks that code changes must preserve.

## 1. Principals & Credential Delegation

- **Unauthenticated clients:** May reach only `/healthz`, `/readyz` (which returns static `"database: unreachable"`, never internal error strings: `internal/web/health.go:27-55`), `/favicon.ico` and `/static/{file}` (`s.assetRoutes` in `internal/web/assets.go:101-123`, registered from `internal/web/server.go:204-212`), and `GET /auth/{login,callback}` (`Service.Routes` in `internal/auth/service.go:199-206`; `POST /auth/logout` authenticates the session and CSRF token itself at `internal/auth/login.go:157-173`, and `GET /auth/proxmox{,/callback}` require `s.liveSession` at `internal/auth/proxmoxlogin.go:34-40,79-85`).
- **Signed-in volunteers (`auth.User` + `proxmox.Credential`):**
  - Authentik OIDC policy bindings gate who may sign in (`internal/auth/login.go:24-152`), using Authorization Code + PKCE (`S256`), `state`, `nonce`, and ID token verification in `internal/auth/identity.go:89-146` via `s.verifier` (`internal/auth/service.go:180-182`: `iss`, `aud` against `oidc.client_id`, signature, expiry, `nonce` at `internal/auth/identity.go:103-105`, and `at_hash` when present at `internal/auth/identity.go:106-110`).
  - A second OpenID exchange against Proxmox (`internal/auth/proxmoxlogin.go:34-150`) verifies that `sess.Username` is non-empty and binds the returned Proxmox ticket by exact byte-for-byte equality (`cred.User != sess.Username + "@" + s.cfg.Proxmox.Realm`, with no Unicode or case folding: `internal/auth/proxmoxlogin.go:125-137`).
- **No ambient Proxmox service credential:**
  - `battleship` refuses to start if `BATTLESHIP_PROXMOX_TOKEN_ID` / `BATTLESHIP_PROXMOX_TOKEN_SECRET` are set in the environment (`noServiceToken` in `cmd/battleship/serve.go:134,302-310`) or if `token_id` / `token_secret` appear in `battleship.toml` (`removedKeys` in `internal/config/config.go:350-363`).
  - Every Proxmox API call in previews, confirms, per-user live status views (`internal/status/views.go:19-106`, keyed by `cred.User`), and background job workers (`internal/jobs/worker.go:199-210`) binds a user credential via `proxmox.Client.As` or `AsSource` (`internal/proxmox/client.go:48-55`, `internal/proxmox/failover.go:46-54`). An unbound or empty credential fails closed with `proxmox.ErrNoCredential` (`internal/proxmox/credential.go:20`, enforced in `doServed` at `internal/proxmox/failover.go:47-54` and `RenewTicket` at `internal/proxmox/credential.go:119-121`).
  - Job retry (`internal/web/jobpages.go:1120-1158`) and confirm (`internal/web/confirm.go:29-146`) re-plan and submit using the **acting user's** own Proxmox ticket, never a previous submitter's credential.

## 2. Trust Boundaries & Entry Points

- **Reverse proxy boundary (`internal/web/middleware.go:84-133`):** `forwarded` unconditionally strips incoming `X-Forwarded-For`, `X-Forwarded-Proto`, `X-Forwarded-Host`, `Forwarded`, and `X-Real-Ip` headers and only parses `X-Forwarded-For` (right-to-left hop walk) and `X-Forwarded-Proto` when `r.RemoteAddr` is within `web.trusted_proxies`.
- **Browser request & state-change boundary:**
  - `limitBody` (`internal/web/middleware.go:27-51`) caps request bodies at 1 MiB (`maxBody = 1 << 20`) before any handler or CSRF form parse runs.
  - Every route outside `/healthz`, `/readyz`, `/static/`, and `/auth/` wraps `s.require` (`internal/web/privileges.go:77-83` → `auth.Service.RequireUser` in `internal/auth/middleware.go:94-155`), requiring a live session, periodic OIDC refresh-token revalidation (`web.session_refresh`), and a usable Proxmox ticket.
  - Every method except `GET` and `HEAD` enforces `Service.csrfProblem` (`internal/auth/middleware.go:117,258-278`; also called by `s.logout` at `internal/auth/login.go:170`), checking that `Origin` matches `s.origin` when `Origin` is present (`internal/auth/middleware.go:262-267`) and verifying the 32-byte per-session `csrf_token` with `subtle.ConstantTimeCompare` (`internal/auth/middleware.go:268-276`).
  - `opConfirm` (`internal/web/confirm.go:29-146`) loads `jobs.Inputs` from the server-stored `store.Preview` row keyed by `(session_id, sha256(nonce))` rather than trusting hidden form fields, re-plans against the cluster, verifies `jobs.Fingerprint(plan) == prev.Fingerprint`, enforces `TypedConfirm()` server-side, and atomically claims the preview (`claimPreview` in `internal/store/previews.go:99-117`) inside `store.CreateJob` (`internal/store/jobs.go:140-188`).
  - `cancelJob` / `mayCancel` (`internal/web/jobpages.go:1055-1104`) authorizes cancellation only when `j.CreatedBy == actor(u)` (`internal/web/ops.go:432-437`) or the caller holds `pods.HoldsOffered` (`internal/pods/access.go:190-202`) on every item's VM (`/vms/<vmid>`) or target pool (`/pool/<pool>`).
- **Redirect & header boundary:**
  - Post-login, error-page, and `<meta http-equiv="refresh">` targets are validated by `safeNext` / `auth.LocalURL` (`internal/auth/next.go:14-52`, `internal/web/render.go:140,259-272`).
  - Proxmox OpenID login start (`proxmoxStart` in `internal/auth/proxmoxlogin.go:62-71`) verifies that the redirect URL returned by Proxmox carries a non-empty `state` query parameter and `http`/`https` scheme, and OIDC logout (`internal/auth/login.go:184-200`) redirects to `s.endSessionURL` discovered from `oidc.issuer` and validated by `webURL` (`internal/auth/service.go:160-162,221-224`).
  - Security headers (`contentSecurityPolicy` and `s.secure` in `internal/web/middleware.go:21-23,59-71`) set `Content-Security-Policy: default-src 'self'; base-uri 'none'; object-src 'none'; frame-ancestors 'none'; form-action 'self' <issuerOrigin>`, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`, and `Strict-Transport-Security` under HTTPS.
- **External control planes (Proxmox API & Authentik IdP):**
  - Proxmox TLS certificates are verified against `proxmox.ca_file` unless `proxmox.insecure_skip_verify` is explicitly set (`ReadCAFile` and `RequireTLSVerify` in `internal/config/config.go:333-344,667-674`, `proxmox.New` in `internal/proxmox/client.go:82-125`).
  - Proxmox path segments use `url.PathEscape` (`internal/proxmox/vms.go`, `internal/proxmox/tasks.go`), and responses are capped at 32 MiB (`maxAnswer = 32 << 20` in `internal/proxmox/client.go:92,170-175`, with tighter per-call caps via `c.capped(limit)` in `internal/proxmox/agent.go:26-35,80-100`).
- **Untrusted cluster data & guest execution (Proxmox QEMU Guest Agent):**
  - Battleship never SSHes into Proxmox nodes or guest VMs; guest setup and live checks run via the Proxmox QEMU Guest Agent API (`AgentExec` in `internal/proxmox/agent.go`).
  - VM `description` notes and configs are treated as untrusted input: `pods.NotesChanges` (`internal/pods/vmconfig.go:206-211`) strips `description` from cloned pod VMs so base-image credentials never leak to team VMs; `CheckDetails`, `dropFormat`, `ParseDetails`, and `CheckNotes` (`internal/pods/details.go:43,108-141,163-170,249-255,391-428`) strip Unicode `Cf` format characters and bound note sizes.
  - `CheckSSHKey`, `pods.Guest.Check`, `GuestCommand`, and `GuestScript` (`internal/pods/guest.go:31-133`) validate every hostname, domain, IPv4 address, prefix, MAC (`macRE`), and canonical OpenSSH CA public key before sending the Linux setup script on stdin to `/bin/sh -c <linuxLocked>` (`internal/pods/guest.go:112,136-284`) or running `powershell.exe ... -EncodedCommand` (`internal/pods/guest.go:103-110,289-356`).

## 3. Crown-Jewel Assets & Secret Invariants

- **Domain-separated AEAD sealing (`internal/seal/seal.go`):**
  - `seal.NewKey(secret, purpose)` derives a 32-byte subkey via `HMAC-SHA256(secret, purpose)` and seals plaintexts as `"v1:" + base64url(nonce || AES-256-GCM(plain, AAD = purpose + "\x00" + binding))` with a 12-byte `crypto/rand` nonce and strict unpadded base64url decoding (`internal/seal/seal.go:33-82`).
  - `oidc.client_secret` (`BATTLESHIP_OIDC_CLIENT_SECRET`) derives keys for OIDC login state cookies (`"battleship oidc login cookie v1"`, AAD `loginCookie = "battleship_oidc_login"`, `internal/auth/loginstate.go:28-58`, `internal/auth/session.go:15`), session refresh/ID tokens (`"refresh token v1"`, AAD `sessionID` and `"id token " + sessionID`, `internal/auth/refreshtoken.go:9-50`), and session Proxmox tickets/CSRF tokens (`"proxmox ticket v1"`, AAD `sessionID + "\x00ticket"` and `sessionID + "\x00csrf"`, `internal/auth/ticket.go:15-58`).
  - `database.seal_key` (`BATTLESHIP_SEAL_KEY`) derives the key for `job_credentials` (`credentialPurpose = "battleship job credential v1"`, AAD `"job:" + jobID`, `internal/jobs/credential.go:35-89`) and the startup key check (`Credentials.CheckKey` using `credentialPurpose`, binding `"check"`, and plaintext `keyCheckText = "battleship seal key check v1"` in `internal/jobs/credential.go:131-144`).
- **One-way token hashing at rest:** Raw 32-byte session tokens, Proxmox OpenID state tokens, and preview nonces are never stored in PostgreSQL—only their SHA-256 hex digests (`auth.HashToken` in `internal/auth/session.go:34-37`, `internal/auth/proxmoxlogin.go:72,92`, `internal/web/preview.go:256`).
- **Credential lifecycle & redaction:**
  - The PostgreSQL trigger `jobs_end_credentials` (`internal/store/migrations/006_delegated_auth.sql:40-47`) deletes a job's `job_credentials` row the moment the job leaves `pending`/`running`, and `store.RenewCredential` (`internal/store/credentials.go:139-140`) deletes lapsed credentials.
  - Ending a session queues its OIDC refresh token in `revocations` in the same SQL statement (`internal/store/sessions.go:250-347`) for background revocation at the IdP (`end`, `queueRevocation`, `RunRevocations`, `DrainRevocations`, and `revoke` in `internal/auth/login.go:202-368`).
  - `seal.Key` and `proxmox.Credential` redact secret material in `String`, `GoString`, and `Format`; `config.OIDC` and `config.Database` redact secrets in `String` and `GoString`.

## 4. Security-Critical Invariants & Sharp Edges

- **UI privilege checks vs. enforcement:** `mayAnywhere`, `mayOn`, `lacks`, and `mayRun` (`internal/web/privileges.go:27-72`) only hide or disable UI controls; `pods.BlockUnpermitted` (`internal/pods/access.go`) and Proxmox's own RBAC on the bound user ticket are the authoritative gates.
- **Test-fake fallbacks must stay test-only:** `asUser` (`cmd/battleship/usertoken.go:11-16`), `accessFor` (`internal/web/server.go:336-340`), and `mayCancel` (`internal/web/jobpages.go:1093-1096`) bypass credential/permission binding only when `pods.API` is not `*proxmox.Client` / `pods.PermissionReader` (used by unit-test fakes). Production startup (`newProxmoxAPI` in `cmd/battleship/main.go:51-55`) must always construct `*proxmox.Client`.
- **Bounded SSE stream lifetime:** SSE handlers (`internal/web/sse.go:183-201`, `internal/web/server.go:300-320`) close after `streamLifetime` (`web.session_refresh`) so revoked sessions are forced back through `RequireUser` on reconnect.
- **Liveness pool isolation:** `store.Store` (`internal/store/store.go:30-37`) isolates `s.liveness` from `s.pool` so web query load cannot starve `/readyz` or worker heartbeats (`internal/jobs/worker.go:273-310`); `heartbeat` must never issue `s.pool` queries synchronously on its loop.

## 5. Explicit Non-Goals & Accepted Risks

- **Shared audit log & lab VM login notes across signed-in volunteers:** All volunteers permitted by Authentik to sign into Battleship can view the job audit trail (`/logs`, `/logs/{id}`) and stored `jobs.inputs` / `jobs.plan` (including `[battleship]` base-image and environment host login notes such as `ImageDetails.Password` written to Proxmox VM descriptions). Those notes hold lab guest credentials for volunteers, not infrastructure secrets.
- **No local user/role table:** Battleship maintains no application-level RBAC table (`internal/store/migrations/006_delegated_auth.sql:18-20`), delegating coarse entry control to Authentik and resource authorization to Proxmox ACLs.
- **Compromised control planes or host secrets:** Battleship does not defend against a compromised Proxmox cluster, Authentik IdP, PostgreSQL database + `BATTLESHIP_SEAL_KEY` / `BATTLESHIP_OIDC_CLIENT_SECRET`, or unauthenticated network floods above PostgreSQL pool limits and `apply.Limits` cluster concurrency slots.
